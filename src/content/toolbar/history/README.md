# History toolbar UI

- Uses the shared origin/database-scoped history repository and serialized background mutations; the repository caps Content at 10 items and Media Library, Templates, Layout, and System at 5 each.
- Quick Info observation keeps the database scope live. Subscription updates win over an older initial read; scope changes and unmounts discard pending results and unsubscribe.
- History is a fixed right-side workspace above the toolbar, with an explicit bottom safety gap and independently scrollable expanded groups.
- History is click-only; hover does not open or close it. Jump, Proxy, and History are mutually exclusive. Compact toolbars omit History.
- Item anchors retain real Content Editor URLs and use the existing navigation service for normal, Ctrl/Cmd, and middle clicks. Scope/database and normalized uppercase braced GUIDs are carried in the URL.
- History rows do not use hover tooltips. Icons are read reactively from cached Quick Info by GUID; misses enqueue foreground Quick Info work, and cache publication rerenders subscribers.
- The empty title wrapper suppresses the parent toolbar's inherited native drag tooltip. Errors remain visible in the panel without optimistic storage writes.
- Agents: Known Sites labels use a storage-first origin/database-scoped subscription, independently of discovery. Content rows render `_: Item` when no Site matches (including unavailable discovery/storage), or `Site: Item` for the longest case-insensitive segment-boundary match. Other categories have no prefix. Rename, removal, and scope changes update prefixes without changing stored names, tooltip metadata, navigation, the per-category caps, or category grouping. Subscription updates win over pending initial reads; old scopes and unmounted results are discarded.
- Agents: Each accepted nonempty Known Sites snapshot defers `lookupKnownSite` for its root paths to the structural discovery entry point. The backend decides whether validation is stale; History never waits for validation to render labels. Deferred requests are discarded after scope changes, newer snapshots, or unmounts. Discovery errors leave stored labels and History interactions usable.
